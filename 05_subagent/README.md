# 05_subagent

这个示例演示了 **子代理（Subagent）** 的使用方式，也就是让主 Agent 把某些任务分发给独立的执行单元去处理。

## 为什么需要子代理

当任务变复杂时，主 Agent 继续自己做所有事情会带来几个问题：

- 上下文越来越长
- 任务之间容易互相干扰
- 不同类型的工作难以分工

子代理的思路就是：

- 主 Agent 负责理解目标、拆分任务、汇总结果
- 子代理负责完成某个局部任务

## 典型适用场景

- 代码搜索
- 文件分析
- 单模块修改
- 独立验证
- 多轮探索型任务

## 工作方式

```text
主 Agent 接到任务
   ↓
判断哪些部分适合交给子代理
   ↓
创建子代理并传递子任务
   ↓
子代理独立执行
   ↓
返回结果给主 Agent
   ↓
主 Agent 汇总并继续下一步
```

## 你可以重点理解的点

### 1. 任务切分

主 Agent 不需要一次性解决所有问题，而是把问题拆成更小的块。

### 2. 上下文隔离

子代理拥有自己的执行上下文，这样可以减少主上下文膨胀。

### 3. 结果汇总

主 Agent 在拿到子代理结果后，再决定下一步动作。

## 运行方式

```bash
uv run 05_subagent/main.py
```

## 关键内容

- `spawn_subagent(...)`：启动子代理
- `task` 工具：让模型显式触发子任务
- 主循环：负责协调多个执行单元

## 后续方向

- 多个子代理并行执行
- 子代理之间互相通信
- 为不同任务类型选择不同子代理模板
- 给子代理增加权限和资源限制

如果你想把 Agent 从“单线程思考”升级成“可分工协作系统”，这个示例是很好的起点。
